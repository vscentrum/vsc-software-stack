### EasyBuild 5.3.0

- released 10 April 2026
- [detailed release notes](https://docs.easybuild.io/release-notes/#release_notes_eb530)
- [highlights](https://github.com/easybuilders/easybuild/releases/tag/easybuild-v5.3.0)
    - support for ROCm-based toolchains (`rfoss` & co)
    - (experimental) support for installing with bwrap (see `--bwrap` and `--bwrap-installpath`), see also EUM'26 talk by Bart & Sam
    - enhance `PythonPackage` and `PythonBundle` to verify Python package names and versions with `pip list`
    - add easyconfigs for update of (common) toolchains: `foss/2026.1`, `intel/2026.1`, `lfoss/2026.1`
        - change in versioning scheme (`2026a` -> `2026.1`)
        - change in cadence for toolchain versions
            - no more two common toolchain versions per year
            - more like once every ~10 months? (time will tell)
- PyTorch w/ CUDA support
    - wheel-based installations, like on sofia
    - what's the plan with stuff that depends on PyTorch?
        - versionsuffix, or not?
        - no versionsuffix used on sofia, although it's a wheel-based installation
        - could maybe use `multi_deps` mechanism for this
            - which was originally used for Python 2 + 3 installations
            - could also be applied to PyTorch from wheels + from source
        - plan is definitely to avoid duplication of easyconfigs
    - see also [PyTorch working group](https://github.com/easybuilders/easybuild/wiki/PyTorch-working-group)
        - time for another meeting, early-mid June?
    - CUDA provided by EasyBuild is used by PyTorch installed via wheels
    - via `CUDA-wheel-bundle` that provides a bunch of fake `nvidia-*` Python packages, but actual libraries are provided by proper dependencies
    - many of the top PyTorch users are self-installing their own PyTorch via `pip` or containers
    - downside of using wheel-based installation
        - relying on upstream to provide binary wheels for your CPU architecture (problem for Arm, POWER)
        - also applies to some packages that depend on PyTorch (missing wheels for Arm)

## Software installations on sofia

- sofia now in pilot phase, mostly working, already used well by users
- stuff missing: OoD, VSC bot to let other VSC sites install software, EESSI (coming via module, CernVM-FS already there)
- EB used for central software stack
- base toolchain: `foss/2025a`, will also install `foss/2026.1` (skipping `foss/2025b`)
- EESSI as a base: not for now, to be reconsidered for sofia
    - also the plan at UGent
    - would be good to coordinate on this
    - VSC-wide Stratum-0 central server?
- support portal for sofia in place, using Zammad
    - VSC staff will have account to help with support tickets (for their site)
- VSC bot will allow VSC sites to help with installations for their users
    - VUB will handle "large" installations (toolchain, Python, R, etc.), via `vsc-apps-bot` (already used by HPC-UGent + VUB)
    - VUB may keep using own tooling for VUB Tier-2 + Tier-1
- plan for production in July'26 (new projects that start after cutoff of 1 June)
- starting grants are already accepted for sofia, will be communicated to VSC users soon, so they can benchmark for project proposals due 1 June
